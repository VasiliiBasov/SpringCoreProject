## 🧠 Что изучено (главное)

| Тема | Суть |
|---|---|
| **Бин** | Объект в контексте Spring |
| **Контекст** | Хранилище бинов + контейнер жизненного цикла |
| **`@Configuration`** | Класс с настройками (включая `@Bean`-методы) |
| **`@ComponentScan`** | Указывает, где искать `@Component`-классы (**Spring Core**, не Boot!) |
| **`@Component`** | «Этот класс — бин, создай его сам через конструктор» |
| **`@Bean`** | Метод, который возвращает бин (для чужих классов или сложной логики) |
| **`@Value`** | Подставляет значение из `properties` (с `:` — default) |
| **`BeanPostProcessor`** | Крючок в конвейере создания бинов (`before` / `after` методы). Применяется только к бинам, созданным **после** его регистрации. **`after` — после `@PostConstruct`**, не до конструктора |
| **`@PostConstruct` / `@PreDestroy`** | JSR-250 (Jakarta Annotation). Init после конструктора и BPP.before, destroy при `ctx.close()`. Пакет `jakarta.annotation`. Для prototype `@PreDestroy` **не вызывается** |
| **AOP: `ProxyFactory`** | Spring оборачивает бин в прокси. Интерфейс → JDK Dynamic Proxy. Класс → CGLIB |
| **SpEL / `@Value`** | `${prop}` — placeholder. `#{expr}` — выражение. `#{${prop} == 'x' ? a : b}` **не работает** — workaround через Java-метод |
| **`@PropertySource`** | Грузит properties. **Последний в списке = высший приоритет** |
| **`@ConfigurationProperties`** | Группировка конфига в POJO. Дефолты из Java-полей. Relaxed binding. **Живёт в Spring Boot**, не в Core |
| **События (Spring 4.2+)** | Любой POJO — `extends ApplicationEvent` не обязателен. `@EventListener` **синхронный** |

## 🎓 Профиль ученика (коротко)

- **Стиль:** отвечает своими словами, формулировки приблизительные — это нормально, я уточняю.
- **Что заходит:** длинные разборы с аналогиями (грузчик/склад, повар/продукты, плагин/коробка), мини-вопросы в конце темы, **мини-экзамены по 1 вопросу за раз без вариантов**, схемы ASCII-арт, объяснение «на пальцах» перед кодом.
- **Что НЕ заходит:** готовый код классов целиком — только подсказки и направление.
- **Любит:** видеть, как ошибка → новая тема. Хочет понимать **зачем**, прежде чем **как**.
- **Ловит неточности** в моих вопросах (вопрос 11А #3, вопрос 12 #2) — это сильная сторона, видно критическое мышление.
- **Правило про время:** не угадывать, всегда `Get-Date`. Если говорит про таймер («пауза», «продолжаю», «сколько уже») — сначала `Get-Date`.
